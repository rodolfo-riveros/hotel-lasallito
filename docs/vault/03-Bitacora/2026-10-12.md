# Bitácora 2026-10-12

## Qué se hizo
- Se leyó el documento de requerimientos y se acordó el alcance con el usuario
  ([[Decisión - Alcance inicial un hotel con POS en fase 1]]).
- Se reactivó el proyecto de Supabase `hotel-la-sallito` ([[Decisión - Supabase como base de datos]]).
- Se creó el repositorio Git y el proyecto Django 5.2:
  - `config/` con configuración separada por entorno;
  - Celery;
  - Docker (Python 3.12) con `docker-compose` (web, worker, redis y db de pruebas);
  - GitHub Actions (ruff, black, verificación de migraciones, pytest con PostgreSQL 17).
- App `core`:
  - Property, Currency, ExchangeRate, TaxRule y AuditLog;
  - modelos base de tiempos, borrado lógico y propiedad;
  - contexto de la petición para auditoría;
  - endurecimiento de PostgreSQL (btree_gist, trigger de auditoría, RLS).
- App `accounts`:
  - User, Permission, Role y PropertyAccess;
  - catálogo de 21 módulos × 6 acciones;
  - los 11 roles de la sección 3;
  - bloqueo tras 5 intentos fallidos (django-axes) y cierre por 30 minutos de inactividad;
  - auditoría de inicios de sesión.
- Pantallas:
  - inicio de sesión;
  - tablero;
  - usuarios (con buscador HTMX);
  - roles con matriz de permisos;
  - configuración del hotel, tipo de cambio e impuestos;
  - auditoría con filtros y exportación CSV;
  - guía visual;
  - contingencia;
  - errores 403, 404 y 500.
- Diseño base:
  - Tailwind con paleta granate y dorado, y colores de estado aptos para daltonismo;
  - modo oscuro, menú según el rol, atajos de teclado, formato peruano de números.
- El comando `seed_pms --demo` carga el hotel de ejemplo y 11 usuarios de práctica.
- **Pruebas: 56 pasan.** Una prueba solo corre en PostgreSQL y se omite en SQLite.
